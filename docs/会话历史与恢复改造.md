# 会话历史与恢复改造规格

> 状态：已确认，作为本轮实现与验收的依据。  
> 实现对照（2026-09-14）：第 1 节「背景与现状」描述的是**改造前**行为。继续/分叉、目录分组、标题与正文清理已按本文落地。分身身份见 `docs/分身Agent规划.md`（`family + nativeSessionId`）。  
> 范围：右侧会话面板、本地会话与 Agent 磁盘历史、原生恢复/分叉、标题和正文清理。  
> 不在范围：删除 Agent 原生历史文件、跨设备同步、树状分支视图、重连已经终止的 PTY 进程。

## 1. 背景与现状

RingCode 当前同时维护两类数据：

- **本地会话**：RingCode 在 `ringcode.db` 中保存的会话标题、工作区、Profile、状态和终端 transcript。
- **磁盘历史**：Claude Code、Codex、Hermes 自己写入用户目录的原生会话文件。

现有行为存在以下问题：

1. 磁盘历史单击后立即启动恢复，容易误操作。
2. RingCode 创建的本地会话通常没有绑定 Agent 原生 session ID，因此没有“继续会话”。
3. “基于此记录新建”目前只是打开同一 Agent 的空白终端，既未恢复也未携带旧上下文。
4. 恢复/新建路径绕过或重新解析 Profile，导致实际启动模式与保存或默认配置不一致。
5. 右侧上方长期展示原始 PTY transcript；ANSI、TUI 重绘和控制字符造成乱码与无用符号。
6. 标题可能从终端装饰、提示符或 Agent 回复中误提取。

本次目标是明确“继续”和“基于此新建”的语义，关联本地记录与原生历史，精简右侧面板，并让失败状态真实可见。

## 2. 名词与产品语义

### 2.1 继续会话

“继续会话”表示：

- 启动一个新的 PTY/CLI 进程；
- 使用 Agent 官方的原生 session ID 恢复同一上下文；
- 不承诺重连已经终止的旧 PTY；
- 恢复本地记录时复用原 RingCode Session，不创建重复本地卡片。

只有存在可用原生 session ID 的记录才能显示为“可继续”。没有原生 ID 的旧本地记录必须明确显示“原会话不可继续”，不能用文本回放冒充恢复。

### 2.2 基于此记录新建

“基于此记录新建”表示创建一个与原会话相互独立的新会话：

- 使用来源会话的 Agent；
- 使用该 Agent 当前默认 Profile 和权限模式；
- 创建新的 RingCode Session 和新的 Agent 原生 session；
- 保存来源关系，在详情中显示“基于《原标题》创建”；
- 原生支持分叉时优先使用原生分叉；不支持时使用清理后的上下文降级。

降级上下文由“会话摘要/标题 + 最近几轮有效对话”组成，过滤 ANSI、TUI 装饰、进度动画和重复工具日志，并限制长度。降级创建仍必须标为新会话。

## 3. 数据来源与关联

继续保留两个来源及右侧两个区域：

- 本地会话；
- 磁盘历史。

RingCode 使用 `tool + nativeSessionId` 作为跨来源关联键：

- 两个区域都保留记录；
- 磁盘条目已与本地记录关联时显示“已关联”；
- 两边的继续/新建操作指向同一原生上下文；
- 两边共用 RingCode 本地显示别名；
- 不修改 Claude/Codex/Hermes 的原始历史文件。

RingCode 启动新 Agent 后，应在原生历史落盘时自动匹配并回填 `nativeSessionId`，使本地会话获得原生恢复能力。匹配应至少校验 Agent、工作目录和启动时间，不能仅把任意最新文件绑定过来。

### 3.1 Session 需要保存的信息

本轮需要补齐以下语义（字段名可按现有代码风格实现）：

- 启动时实际使用的 Profile；
- 启动时实际使用的权限模式；
- 原生 session ID；
- 是否可原生恢复；
- 来源 RingCode Session（分支关系，可选）；
- 用户显示别名（磁盘历史按关联键保存）。

持久化迁移必须兼容已有 Session 和 TerminalTab 快照。

## 4. Agent 能力矩阵

以下命令以本机当前安装版本的 `--help` 为依据；实现必须通过 Adapter 能力描述生成参数，不能继续假设所有 Agent 都统一使用 `--resume`。

| Agent | 恢复指定会话 | 原生分叉 | 本轮策略 |
| --- | --- | --- | --- |
| Claude Code | `claude --resume <id>` | `claude --resume <id> --fork-session` | 恢复和分叉均走原生能力 |
| Codex | `codex resume <id>` | `codex fork <id>` | 使用子命令，不使用伪造的 `--resume` |
| OpenCode | `opencode --session <id>` | `opencode --session <id> --fork` | 会话列表与正文通过公开 CLI 获取，不读取内部数据库 |
| Antigravity CLI | `agy --conversation <id>` | 仅提供会话内 `/fork` | 恢复走原生能力，RingCode 外部分叉走受限上下文降级 |
| Hermes | `hermes --resume <id>` | 当前帮助中未确认独立分叉 | 恢复走原生能力，分叉走上下文降级 |
| 自定义 Agent | 仅在配置了恢复参数时支持 | 默认不支持 | 能力不足时明确降级或禁用 |

参数生成同时遵循：

- **继续本地会话**：优先使用 Session 保存的 Profile 和权限模式；保存的 Profile 已不存在时回退到该 Agent 当前默认 Profile。
- **继续磁盘历史**：使用该 Agent 当前默认 Profile 和默认权限模式。
- **基于此新建**：使用来源 Agent 当前默认 Profile 和默认权限模式。
- 恢复/分叉参数不得静默吞掉明确保存的 Profile 参数或权限参数。

## 5. 工作区与失败处理

### 5.1 工作区

- 恢复时优先使用历史记录的原工作目录。
- 原目录不存在、不可访问或不在允许根目录时，提示用户选择替代目录。
- 不允许静默切换到当前工作区。

### 5.2 状态

- 启动恢复前将复用的本地 Session 标为 `running`。
- PTY spawn 抛错：标记 `failed`，显示具体错误。
- 恢复/分叉进程非零退出：标记 `failed`，提示“原会话未恢复”或“分支创建失败”。
- 正常退出：标记 `ended`。
- 同一 Session 已有运行中的终端时，禁止重复创建恢复终端，改为激活已有终端。
- 恢复失败后提供“基于此记录新建”，但不自动降级为空白终端。

## 6. 右侧面板交互

### 6.1 当前会话

右侧上方保留紧凑的“当前会话”卡片，只展示：

- 清理后的标题；
- Agent；
- 工作区/目录；
- Profile；
- 运行状态；
- 必要操作。

不再常驻展示正文。

### 6.2 历史列表

继续保留“本机会话 / 磁盘历史”两个切换区域：

- 单击：仅选中；
- 双击：打开历史详情；
- 右键或行尾 `…`：打开操作菜单；
- 菜单包含：查看、继续会话、基于此新建、重命名；
- 磁盘历史单击不得启动进程；
- 不可恢复的记录将“继续会话”禁用并说明原因；
- 已关联的磁盘记录显示“已关联”。

### 6.3 历史详情

历史详情在中央大弹窗中按需打开：

- 磁盘 JSONL 优先解析为用户消息、Agent 回复和必要工具信息；
- 本地 transcript 或未知格式降级为清理后的纯文本；
- 支持文本搜索和复制；
- 顶部提供继续、新建和重命名；
- 不向普通界面展示未经清理的原始控制数据。

## 7. 标题、正文与别名

### 7.1 自动标题

自动标题优先级：

1. 用户手动重命名（本地别名），一旦设置不再被自动覆盖；
2. Agent 原生总结标题：Claude Code 的 `ai-title` / `summary`，Codex 的 `~/.codex/session_index.jsonl` `thread_name`，OpenCode `session list` 的 `title`；
3. 首条有效用户消息（跳过 hook 倾倒、tool_result、附件和子 Agent）；
4. 占位标题（如「Claude 会话」）或「未命名会话」。

不得把终端 TUI/PTY transcript 启发式结果当作列表标题；那会把框线、进度条和系统提示显示成乱码。关联到原生会话后，只要仍是自动标题，就继续用更新后的原生总结覆盖。Antigravity 公开缓存不提供会话标题，仍显示 `Antigravity · 工作区名`。

清理内容包括：

- ANSI/OSC/CSI/DCS 控制序列；
- 退格、回车覆盖和不可见控制字符；
- 提示符、Markdown 前导标记；
- 主要由框线组成的 TUI 装饰；
- 进程退出提示、启动提示和明显的状态日志；
- 标题首尾的 `> ❯ │ ╭─ # *` 等无意义符号。

自动生成标题不能把 `autoTitled` 提前改成手动标题状态；后续出现更可靠的 Agent 原生总结标题时仍可校正。用户主动重命名后才永久停止自动改名。

### 7.2 重命名

- 本地 Session 使用现有 Promise 式 `PromptModal`。
- 磁盘历史重命名写入 RingCode 本地 alias map，不修改 JSONL。
- 已关联的本地与磁盘记录使用同一别名并同步显示。
- 手动别名始终优先于自动标题。

## 8. CC Switch 兼容性

RingCode 仍通过正常 CLI 启动 Claude Code，并且不使用 `--no-session-persistence`。因此 Claude Code 会继续把原生历史写入 `~/.claude/projects`：

- CC Switch 可以继续扫描并识别这些原生会话；
- CC Switch 不读取 RingCode 的 `ringcode.db`，因此看不到 RingCode 独有的别名、收藏和运行状态；
- 本轮不得改变 Agent 原生历史的默认存储位置或关闭持久化。

## 9. 实施顺序

1. **纯函数与类型**：Adapter session capability、统一启动参数、标题/正文解析、上下文降级构建。
2. **持久化模型**：Session 启动配置、来源关系、磁盘 alias、兼容迁移。
3. **原生历史关联**：安全扫描、真实 session ID 提取、按 Agent/cwd/时间匹配及 Renderer IPC。
4. **终端生命周期**：准确 Profile/权限、resume/fork/new 三种动作、自动回填 ID、非零退出状态。
5. **右侧面板**：紧凑当前会话卡、选择与菜单行为、继续/新建/重命名。
6. **详情弹窗**：结构化历史、纯文本降级、搜索和复制。
7. **样式与可访问性**：键盘关闭、禁用态、焦点、亮暗主题。
8. **验证**：按下一节执行自动与人工验收。

## 10. 验收标准

### 10.1 自动测试

- Claude/Codex/Hermes 分别生成正确的 new/resume/fork 参数。
- resume/fork 不丢失应保留的 Profile 参数和权限模式。
- Hermes 分叉正确选择文本上下文降级。
- transcript 清理覆盖 ANSI、OSC、回车覆盖、退格、TUI 框线和状态日志。
- 标题优先取 Agent 原生总结（Claude ai-title、Codex thread_name、OpenCode title），拒绝 hook/TUI 噪声，手动别名不被覆盖。
- 原生历史匹配必须同时满足 Agent、cwd、时间窗口。
- 已有关联本地 Session 时能够识别磁盘重复项。
- 应用重启后的状态迁移仍将运行中终端置为 orphaned、Session 置为 interrupted。

执行：

```text

npm run typecheck
npm run build
```

### 10.2 Electron 人工验收

1. 从 RingCode 启动 Claude，新建有效对话；确认本地卡片获得原生 session ID 和“可继续”状态。
2. 结束后点击本地“继续会话”；确认恢复同一 Claude 上下文并复用原本地卡片。
3. 对同一记录执行“基于此新建”；确认产生独立 session ID、使用 Claude 当前默认模式，并显示来源关系。
4. 对 Codex 重复恢复和分叉测试，确认使用 `codex resume` / `codex fork`。
5. 对 Hermes 测试恢复；分叉确认使用上下文降级且明确为新会话。
6. 磁盘历史单击只选中，双击打开详情，右键和 `…` 菜单行为一致。
7. 重命名磁盘历史；确认 JSONL 未修改、本地与磁盘关联卡片同步显示别名。
8. 测试原目录失效、无效 session ID、CLI 非零退出和重复点击恢复。
9. 检查详情正文无 ANSI/TUI 乱码，标题前无提示符和框线字符，搜索与复制可用。
10. 打开 CC Switch 刷新会话统计，确认 RingCode 创建的 Claude 原生会话仍能被发现。
