# 发版与打包

> 更新日期: 2026-09-15
> 对照：`electron-builder.yml`、`package.json` 的 `electron:build`、`electron/appUpdate.ts`

应用显示名仍是 **金刚琢**（安装快捷方式、解压后的 `金刚琢.exe`）。GitHub Release **附件文件名必须是 ASCII**，否则网页上传常会变成 `default.zip`，设置里「检查更新」也会对不上包装。

---

## 1. 怎么打

```bash
npm run electron:build
```

产物在 `release/`：

| 渠道 | 文件名 | 给谁用 |
| --- | --- | --- |
| 免安装 | `RingCode-<version>-x64.zip` | 解压后运行里面的 `金刚琢.exe` |
| 安装版 | `RingCode-<version>-x64.exe` | NSIS 安装向导 |

规则写在 `electron-builder.yml` 的 `artifactName: RingCode-${version}-${arch}.${ext}`。不要改回 `${productName}-…`，`productName` 是中文「金刚琢」。

**不要：**

- 用 `electron-builder --dir` 再自己压 zip（文件名、目录结构容易和正式产物不一致）
- 把 zip / exe 改成中文名再上传
- 只上传 zip 或只上传 exe（两个渠道的「检查更新」各认一种）

---

## 2. 怎么传到 GitHub

网页拖文件 **可以**，前提是附件名已经是 ASCII（字母、数字、`. - _`）。`RingCode-0.4.2-x64.zip` 这种没问题；出过问题的是 `金刚琢-….zip`，不是网页本身。

传完立刻打开 Release 页核对附件名。若又变成 `default.zip`，删掉该附件，用原名重传：

```bash
gh release upload v0.4.2 release/RingCode-0.4.2-x64.zip release/RingCode-0.4.2-x64.exe --clobber
```

新建 Release 也可以一次带上文件：

```bash
gh release create v0.4.2 release/RingCode-0.4.2-x64.zip release/RingCode-0.4.2-x64.exe --title "v0.4.2" --notes "..."
```

Tag 用 `v` + `package.json` 的 version，例如 `0.4.2` → `v0.4.2`。

---

## 3. 和「检查更新」的关系

- 更新检查读取 latest 的版本号、发布日期和 Release Notes
- 免安装版与安装版都认 **latest 里的 `.exe`**（不含名字带 `portable` 的），应用内下载安装；`.zip` 只用于手动下载分发
- 点击「立即升级」后显示下载进度，校验 GitHub 仓库来源与 asset size，随后启动 NSIS 安装程序并退出 RingCode，不打开浏览器
- 仍只需上传 ZIP 与 EXE 两个附件，不需要 `latest.yml`
- latest 的版本号不高于当前应用时，会显示「已是最新」——要测「发现新版本」，需要发一个更高 tag，或临时把本机 `package.json` version 改低（测完改回，不要提交）

## 4. 本地验包

打包后至少确认 ZIP 与 NSIS EXE 都是本次生成，并对 ZIP 做一次实际解压。2026-09-15 的 0.4.2 产物已验证：ZIP 可正常解压，包内版本为 0.4.2，解压目录可在不提权的情况下完整删除。
