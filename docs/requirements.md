## 1. 文档目的

本文档定义“金刚琢”首个可用版本的产品范围、功能需求、交互原则、技术约束和验收标准，用于后续原型设计、技术设计、开发排期和测试验收。

本文档中的优先级含义如下：

- P0：MVP 必须实现，缺失则不能发布。
- P1：首个正式版本建议实现，可在 MVP 验证后补充。
- P2：后续规划，不进入首版承诺。

## 2. 产品概述

### 2.1 产品定位

金刚琢是一款以本地工作区为中心的 Windows 原生 AI 工作台。用户在一个应用中完成文件管理、代码或文本编辑、内容预览、终端操作、多 Agent 启动与切换、会话记录和 Skill 管理，不必再单独打开终端、资源管理器或在各个 Agent 窗口之间来回切。

金刚琢不是简单的 AI 命令启动器。它负责组织工作区、文件、终端、AI 会话和配置。内置 Claude Code、Codex、Hermes；新的 CLI Agent 通过适配器表或设置里的自定义项接入，不必改架构。

### 2.2 产品名称含义

“金刚琢”寓意包罗万象、吸收并驾驭优秀工具。产品对外强调统一工作入口，同时保持对 Claude Code、Codex 及后续其他工具的开放兼容。

### 2.3 默认 AI 工具

- Claude Code、Codex、Hermes 均在顶部工具栏提供独立快捷入口，点击哪个即启动哪个。
- 首次启动或未配置时，默认工具为 Claude Code。
- Codex 是内置的第二 AI 工具；Hermes 是内置的第三 AI 工具。
- 用户可在设置中增加自定义命令行 AI 工具（AIT-009）；内置适配器位于 `src/lib/agents.ts`，新增内置 Agent 只需追加一条定义。
- Claude Code 启动前可选择默认 / Auto / 危险启动（`--dangerously-skip-permissions`）。
- 新建配置方案时默认工具为 Claude Code；用户修改默认工具后应记住其选择。

## 3. 产品目标与边界

### 3.1 MVP 目标

1. 用户可以在金刚琢内打开文件夹并完成文件浏览、编辑和常见格式预览。
2. 用户可以通过内置终端一键启动 Claude Code，或切换到 Codex。
3. 用户可以查看、搜索、切换和恢复历史 AI 会话。
4. 用户可以保存不同的工具、模型、命令参数和环境配置方案。
5. 用户可以调整各区域大小、显示状态和分屏布局，并在重启后恢复。
6. 用户可以统一管理本地 Skill 库，完成导入和查看。
7. 应用以 Windows `exe` 形式安装和运行，不要求安装或启用 WSL。

### 3.2 非目标

以下内容不属于 MVP：

- 不实现自研大模型或自研 Agent 运行时。
- 不替代 Claude Code、Codex 自身的推理和文件修改能力。
- 不承诺完全兼容各工具所有未公开配置或内部会话格式。
- 不提供完整 Office 套件能力。
- 不提供多人实时协作、云端账户同步和插件市场。
- 不支持 WSL、Linux 或 macOS。
- 不在 MVP 中实现多个 AI 自动辩论或复杂 Agent 编排。
- 不在 MVP 中实现 Skill 兼容判断和到 Claude Code/Codex 的同步。

### 3.3 核心原则

- 工作区优先：所有文件、终端、会话和运行配置归属于一个工作区。
- 默认即用：检测到 Claude Code 后，一次点击即可在当前工作区启动。
- 可解释：启动命令、工作目录、模型配置和同步目标对用户可见。
- 不锁定：用户可以切换 Codex 或添加自定义 CLI。
- 本地优先：项目文件、配置和会话索引默认保存在本机。
- 安全执行：软件不在用户不知情的情况下执行项目命令或修改 AI 工具配置。启动前确认面板必须展示将要执行的命令与权限模式；Claude Code 的 Auto 模式必须是可见选项，不得在用户未看到该选项时静默附加。

## 4. 目标用户与典型场景

### 4.1 目标用户

- 使用 Claude Code 或 Codex 进行开发的 Windows 用户。
- 使用 AI 编写 Markdown、技术文档和结构化文本的用户。
- 希望统一管理多个项目、终端、AI 会话及 Skill 的重度 AI 用户。
- 不希望配置 WSL，希望直接使用 PowerShell 和 Windows 原生 CLI 的用户。

### 4.2 核心场景

#### 场景 A：继续昨天的 Claude Code 工作

用户打开金刚琢，应用恢复上次工作区和布局。用户在历史会话中搜索项目或关键词，打开昨天的 Claude Code 会话，查看原记录，并在工具支持恢复时继续原上下文。

#### 场景 B：在项目中启动新的 AI 会话

用户选择一个项目文件夹，点击 Claude Code 快捷入口。金刚琢按选定配置方案在当前工作区启动新终端，记录会话元数据并实时显示终端输出。

#### 场景 C：切换 AI 工具处理同一项目

用户关闭或保留当前 Claude Code 会话，在相同工作区中启动 Codex。两个会话分别保留历史、标题、工具类型和启动配置，互不覆盖。

#### 场景 D：编辑并预览文档

用户在左侧选择 Markdown 文件，在中间编辑内容，在右侧实时查看渲染效果，下方终端继续运行 Claude Code。所有区域可按需要调整大小或暂时隐藏。

#### 场景 E：管理 Skill

用户将一个 Skill 导入金刚琢 Skill 库，查看其名称、来源、作用域和内容指纹。第一版仅做本地库管理；后续版本再支持对 Claude Code 和 Codex 的兼容判断与同步。

## 5. 信息架构与主界面

### 5.1 默认布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ 工作区切换 | 全局搜索 | 命令面板 | Claude Code | Codex | 设置   │
├─────────────┬────────────────────────────┬───────────────────────┤
│ 工作区      │ 编辑器 / 目录 / Diff       │ AI 会话 / 文件预览    │
│ 文件树      │                            │                       │
│ 收藏夹      ├────────────────────────────┤ 历史 / Markdown /     │
│ 最近项目    │ 终端 / Git（P1）           │ 图片 / PDF（P1）/信息 │
└─────────────┴────────────────────────────┴───────────────────────┘
```

> 上图是信息架构示意。Git 状态与 PDF 预览的优先级以第 6 节为准（均为 P1），不作为 MVP 验收项。Markdown 编辑与预览同时显示见 EDT-005（P0）。

### 5.2 区域规则

- 左侧栏：工作区、文件树、收藏夹和最近项目。
- 中间主区域：目录内容、文件编辑、搜索结果和文件差异。
- 中间下方：终端和 Git 信息。
- 右侧栏：当前 AI 会话、历史会话列表和文件预览。
- 顶部工具栏：工作区切换、全局搜索、命令面板、AI 快捷启动和设置。
- 所有主要区域支持拖动调整尺寸、隐藏和恢复。
- 编辑器、终端和右侧面板支持标签页切换。
- 应用重启后恢复上次工作区、打开文件、标签页和布局比例。

### 6.7 历史对话与会话切换

#### 6.7.1 会话定义

一次 AI 会话是由金刚琢启动或登记的 Claude Code、Codex 或自定义 AI 工具运行记录。每个会话至少包含：

- 会话 ID
- 标题
- AI 工具类型
- 所属工作区
- 配置方案
- 创建时间、最后活动时间和结束时间
- 启动工作目录
- 运行状态
- 可检索的文本记录
- 工具原生会话标识（工具提供时）
- 是否支持恢复原上下文

#### 6.7.2 功能需求

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| HIS-001 | P0 | 每次从金刚琢启动 AI 工具时自动创建会话记录。 |
| HIS-002 | P0 | 历史列表按工作目录分组；当前工作区及其子目录优先，其他目录按最近活动时间倒序，组内会话按最后活动时间倒序，并展示标题、工具、工作区、时间和状态。 |
| HIS-003 | P0 | 用户可按标题、工作区和会话文本关键词搜索历史。 |
| HIS-004 | P0 | 用户可按 AI 工具、日期和工作区筛选历史。 |
| HIS-005 | P0 | 用户可切换会话并查看已保存的对话或终端文本记录。 |
| HIS-006 | P0 | 用户可重命名、收藏和删除历史会话；删除前必须确认。 |
| HIS-007 | P0 | 删除金刚琢历史不得删除工作区文件，也不得在未提示时删除工具自身的数据。 |
| HIS-008 | P0 | 当 AI 工具提供原生恢复机制时，显示“继续会话”并尝试恢复原上下文；恢复失败或标识不可用时退回 HIS-009。 |
| HIS-009 | P0 | 当工具不支持恢复或恢复数据已丢失时，只允许查看记录或基于历史新建会话，并明确提示二者差异。 |
| HIS-010 | P0 | 应用异常退出后，保留已落盘的会话记录，并将未正常结束的会话标记为“已中断”。 |
| HIS-011 | P0 | 历史记录不得保存 API Key、访问令牌等被识别为敏感信息的配置值。 |
| HIS-012 | P1 | 优先使用各 Agent 原生总结标题（Claude `ai-title`、Codex `thread_name`、OpenCode `title`）；缺失时回退到首条有效用户消息，并允许用户修改。不从终端 TUI 输出抽标题。 |
| HIS-013 | P1 | 支持将会话记录导出为 Markdown 或纯文本。 |
| HIS-014 | P1 | 支持固定历史面板，并在多个活跃会话间快速切换。 |
| HIS-015 | P1 | 支持通过公开接口或只读公开目录检索 Claude Code、Codex、OpenCode、Antigravity CLI 与 Hermes 的本机会话，并在工具支持时原生继续或分叉。OpenCode 只调用公开的 `session list` / `export`；Antigravity 只读取公开的最近会话映射，不得解析工具的内部数据库 schema。 |

#### 6.7.3 会话保存边界

- 金刚琢保证保存自己的会话索引和可读取的终端文本记录。
- “查看历史”不等同于 AI 可以继续之前的上下文。
- “继续会话”通过工具适配器调用对应工具的恢复能力；获取工具原生会话标识只允许使用公开 CLI 接口或公开会话目录，不得深度解析未公开的内部数据库 schema。
- 工具升级若改变会话存储结构，可能导致“继续会话”失效；此时自动退回“基于历史新建会话”并提示用户，相应适配器需跟进适配。
- 对 ANSI 控制字符和终端交互内容进行清理后再建立全文索引，原始输出可按保留策略存储。
- 用户可在设置中关闭会话正文保存，此时只保存标题、工具、工作区和时间等元数据。

## 7. 关键交互流程

### 7.1 首次启动

1. 应用显示欢迎页并说明本地数据位置。
2. 检测 Windows 版本、PowerShell、Claude Code 和 Codex。
3. Claude Code 可用时标记为默认；不可用时提供手动配置入口。
4. 用户选择本地文件夹作为第一个工作区。
5. 应用进入主界面，焦点位于文件树或 Claude Code 启动入口。

### 7.2 启动 Claude Code

1. 用户打开工作区。
2. 用户点击顶部 Claude Code 按钮。
3. 应用读取该工作区的默认 Claude Code 配置方案。
4. 应用创建专用终端和新的历史会话记录。
5. 应用以工作区根目录为当前目录启动命令。
6. 右侧显示当前会话信息，历史列表出现新记录。
7. 启动失败时终端保留错误，历史标记为失败。

> 点击 Codex 入口同理，使用 Codex 对应配置方案在当前工作区启动。

### 7.3 查找并继续历史会话

1. 用户打开历史面板。
2. 用户输入关键词，或按工具、工作区、日期筛选。
3. 用户选择会话，查看保存的文本记录。
4. 若存在受支持的原生恢复能力，用户点击“继续会话”。
5. 应用在原工作区或用户确认的新目录中启动恢复命令。
6. 若无法恢复，应用提供“基于此记录新建会话”，并明确不会自动恢复原上下文。

### 7.4 Skill 导入与管理

1. 用户从本地文件夹导入 Skill 到金刚琢 Skill 库。
2. 应用计算内容指纹并记录名称、来源、作用域和更新时间。
3. 用户在库中查看、搜索和管理已导入的 Skill。
4. 后续版本再支持兼容判断与到 Claude Code/Codex 的同步。

## 8. 数据设计

### 8.1 本地数据实体

- Workspace：工作区路径、显示名、最后打开时间和布局引用。
- Session：AI 会话元数据、状态、工具原生会话标识和记录引用。
- Transcript：清理后的可搜索文本、原始输出引用和保留策略。MVP 可将清理后的正文存在 Session 上；达到体积上限后截断。SQLite FTS 与原始输出分文件是目标形态，不阻塞 MVP 验收。
- ToolProfile：名称、作用域（全局/工作区）、工具、命令、参数、模型、工作目录、环境变量引用、终端策略和凭据引用。
- TerminalProfile：Shell 路径、参数、编码和外观设置。
- Skill：来源、内容指纹、作用域和更新时间。
- Layout：区域显隐、尺寸、标签页和分屏结构。
- AppSetting：主题、快捷键、默认工具和隐私设置。

### 8.2 存储原则

- 结构化数据建议使用 SQLite。
- 大体积终端原始记录可分文件保存，SQLite 仅保存索引和路径。
- 使用 SQLite 全文检索能力建立历史会话搜索索引。
- 敏感凭据只存入 Windows Credential Manager，数据库保存凭据引用。
- 数据库和配置文件写入采用原子更新，避免异常退出后损坏。
- 提供本地数据目录入口和会话数据清理功能。

### 8.3 默认保留策略

- 会话元数据默认长期保留，直到用户删除。
- 会话正文默认保存，用户可关闭或设置保留期限。
- 终端原始记录需要设置体积上限，达到上限后优先清理最旧且未收藏的记录。
- 删除前展示将删除的内容范围，收藏会话不参与自动清理。

## 9. 安全与隐私要求

1. Electron 渲染进程不得直接获得完整 Node.js 权限。
2. 必须启用 `contextIsolation`，通过受控 preload API 和 IPC 访问文件、终端及凭据。
3. IPC 接口必须校验工作区路径、操作类型和参数，不接受任意脚本执行请求。
4. 启动外部命令时使用参数数组或可靠的转义策略，避免路径和输入造成命令注入。
5. API Key、令牌和密码不得写入日志、数据库、会话全文或导出文件。渲染进程不得通过 IPC 读取明文凭据；仅主进程注入子进程环境。
6. 打开外部链接前校验协议，仅允许 `http:` / `https:`，并在系统浏览器中打开；禁止网页内容直接调用本地能力。
7. HTML 和 Markdown 预览必须禁用或隔离不受信任脚本。
8. 文件删除、Skill 覆盖和关闭运行进程等不可逆或高影响操作必须确认。
9. 应用更新包应进行代码签名并校验来源。
10. 默认不上传工作区、会话或使用统计；未来增加遥测时必须由用户主动同意。

## 10. 非功能需求

### 10.1 兼容性

- MVP 目标系统为 Windows 10 (1809+) 和 Windows 11 x64。
- 不依赖 WSL、Docker 或 Linux 命令。
- 路径处理必须支持盘符、UNC 路径、空格和中文字符。
- 必须支持 PowerShell 原生命令行习惯和 Windows 换行符。
- Windows on ARM 不属于 MVP 验收范围，后续根据用户需求评估。
- 终端基于 ConPTY，要求 Windows 10 1809 及以上版本。
- UI 首版仅提供简体中文，英文等多语言后续按需支持。

### 10.2 性能

- 常规设备上冷启动目标不超过 5 秒，恢复窗口后 2 秒内可操作。
- 包含 10,000 个文件的工作区首次文件树可用目标不超过 3 秒。
- 历史记录达到 10,000 个会话时，关键词搜索结果目标在 1 秒内返回首屏。
- 调整分栏大小时保持连续响应，不出现明显卡顿或内容重叠。
- 文件监听、索引和预览任务不得阻塞终端交互。

### 10.3 稳定性

- 单个终端、预览器或 AI 工具异常退出不得导致整个应用退出。
- 应用异常退出后，下次启动能恢复已保存的工作区和布局。
- 外部工具升级或配置变化后，用户可重新检测并修正路径。
- 日志需要区分应用日志、工具输出和会话正文，并支持脱敏。

### 10.4 可访问性

- 核心操作支持键盘完成。
- 图标按钮提供可访问名称和悬浮提示。
- 焦点状态清晰，标签页和分栏顺序可预测。
- 正文和关键控件满足基本颜色对比度要求。

## 11. 技术栈建议

### 11.1 推荐方案

- 桌面框架：Electron
- 开发语言：TypeScript
- UI：React + Vite
- 编辑器：Monaco Editor
- 终端：xterm.js + node-pty + Windows ConPTY
- 状态管理：Zustand
- 本地数据库：SQLite
- 布局：成熟的 Dock/Panel 布局库，选型前验证嵌套分屏、状态持久化和高 DPI
- 凭据：Windows Credential Manager 的受控主进程封装
- 工具适配：主进程内建工具适配器层，封装各 AI 工具的会话标识获取、恢复命令与配置注入
- 打包：electron-builder 或 Electron Forge，最终输出签名的安装版 `exe`

### 11.2 选择理由

产品的主要技术风险集中在 Windows 终端、子进程、文件监听、编辑器和多个 CLI 的集成。Electron/Node.js 在这些领域有成熟生态，使用 TypeScript 可以统一主进程、preload 和渲染层的类型契约。相比 Tauri，Electron 的安装包和运行内存较大，但首版开发和兼容风险更低。

### 11.3 进程边界

```text
Renderer（React）
  │ 受控 IPC
Preload API
  │
Electron Main
  ├── 工作区与文件服务
  ├── PTY/进程管理
  ├── 会话记录与索引
  ├── 工具适配器层（Claude Code / Codex / Hermes / 自定义 CLI）
  ├── SQLite
  └── Windows Credential Manager
```

## 12. MVP 验收标准

### 12.1 核心验收场景

1. 在一台未启用 WSL 的 Windows 10 或 Windows 11 x64 电脑上安装并启动金刚琢。
2. 打开包含中文和空格路径的本地项目，文件树正确显示且可编辑文件。
3. 默认使用 PowerShell，在项目根目录创建终端并正确执行原生命令。
4. 已安装 Claude Code 时，点击主快捷入口即可创建会话并在当前工作区启动。
5. 可切换 Codex，两个工具使用独立配置和历史记录。
6. 创建至少 20 个会话后，可按关键词、工具和工作区找到目标会话。
7. 选择历史会话后可查看文本记录；可恢复时继续原会话，不可恢复时提示并新建会话。
8. 重启应用后恢复工作区、布局、打开文件、历史列表和配置方案。
9. Markdown 文件可以一边编辑一边预览，外部修改时不会静默覆盖本地内容。
10. 左、中、右及终端区域均可调整尺寸和隐藏，在 125%/150% 缩放下不重叠。
11. 导入一个 Skill 后，可在 Skill 库中查看其名称、来源、作用域和内容指纹。
12. API Key 存入 Windows Credential Manager，在配置文件、日志和导出会话中搜索不到明文。
13. Claude Code 启动失败或应用异常退出后，已有会话记录不丢失，并显示正确状态。

### 12.2 发布阻断条件

- 在无 WSL 环境无法运行核心功能。
- Claude Code 不是默认工具或无法从当前工作区启动。
- 会话历史无法搜索、切换或在重启后保留。
- 关闭或切换工作区会静默丢失未保存文件。
- 路径含空格或中文时无法启动终端/AI 工具。
- 敏感凭据以明文写入本地配置、日志或历史记录。
- 分栏在常用 Windows 缩放比例下发生明显重叠或不可操作。
