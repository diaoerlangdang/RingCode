## 1. 一句话

从 Claude Code / Codex **复制分身**：会话历史共用默认家目录，**Key、URL、模型、权限各自独立**。继续会话默认用上次打开的入口，可改选同家族原版或另一个分身。

**配置属于分身，会话只记住上次使用的入口。** 每次新建、继续、分叉都读取该入口最新的 Key、URL、模型、权限；修改配置后下次启动生效，已运行进程保持本次启动配置。

## 2. 目标与非目标

### 要做成

- 原版和分身可在顶栏并排，显隐与收纳按第 15 节规划；每个分身一套配置，所有项目、顶栏和系统启动器一致。需要不同设置就另建分身。
- 用户无需为换线路修改原版配置。Claude 共享 `~\.claude`，Codex 共享 `~\.codex`；本机记录与原生历史可关联。
- 每个分身有命令名；创建时尝试生成系统启动器，用户自行决定是否加入 PATH。
- Key 存 Windows 凭据管理器，脚本及非敏感配置只留引用；支持删除分身、单清 Key 和一键全清。

### 不做

- 不隔离 CODEX_HOME / Claude 家目录，不自动改用户 PATH 或主配置。
- 第一版只复制原版 Claude Code / Codex；不能从分身再复制，不扩展其他 Agent 的复制能力。
- 历史不按分身增加筛选芯片；继续沿用本机/磁盘 Tab 和目录分组。
- 清本地数据不顺带删密钥；具体遗留资源处理见第 10 节。

## 3. 已拍板决策

| 项 | 决定 |
| --- | --- |
| 创建必填 | 显示名、命令名 |
| 创建选填 | Key、URL、模型，可后补；模型为空表示 CLI 当前默认值 |
| 配置范围 | 每分身一套全局配置，所有项目及启动入口共用，不设工作区覆盖 |
| 继续默认 | 本机及已关联磁盘取上次入口；未关联磁盘默认家族原版 |
| 继续配置 | 取所选入口当前设置，旧会话保存的 Profile/权限不决定下次启动 |
| 点继续 | 无活跃终端时直接启动；已有活跃终端则激活它 |
| 换入口 | 同家族可换；必须先结束当前终端；成功打开后更新上次入口 |
| 分叉默认 | 上次打开的入口及其当前配置；新会话独立，来源入口不变 |
| 缺 Key | 分身所有启动入口都拦截；原版无 Key 仍可走 CLI 登录态 |
| 权限 | 分身独立保存默认 / Auto / 危险，继续也使用当前选择 |
| 系统命令 | 创建时尝试生成；失败不挡顶栏，但显示原因和重试入口 |
| 删除分身 | 先结束该分身全部终端；删关联配置、Key 和所属文件；会话保留，后续回退原版 |
| 单清 Key | 先结束该分身终端；保留配置及启动器，分身标缺 Key |
| 全清 | 先结束全部 RingCode AI 终端并提示关闭外部会话；保留分身设置，补 Key 后重建启动器 |
| 命令名 hjcodex | 允许；旧 PowerShell 函数可能优先命中，检测和提示边界见第 9 节 |

## 4. 产品模型

分身是原版的别名入口，不是空白自定义 CLI。真正执行的仍是 `claude` / `codex`，恢复和分叉能力、历史目录、Codex 终端滚动兼容处理跟随家族；分身自己拥有显示名、命令名、稳定身份、当前配置、凭据引用和启动器。

- `claude` 家族：原版 Claude Code + 从它复制的分身。
- `codex` 家族：原版 Codex + 从它复制的分身。

跨家族禁止继续/原生分叉。共享历史不能可靠证明某段 jsonl 使用了哪把 Key；上次入口只信 RingCode 自己记录的启动行为。

## 5. 数据与现有规格衔接

### 5.1 数据身份

沿用现有 AgentDef / ToolProfile / Session 存储，字段名可调整：

| 对象 | 约束 |
| --- | --- |
| AgentDef | 分身 id 使用不可复用稳定值（如 UUID），与命令名分离；同名重建是新分身。family 指向原版家族；继承原生 session、permission、modelArgs、initialPrompt、icon 等能力，不复制原版凭据引用。 |
| ToolProfile | tool = 分身 id，每分身仅一份全局配置；command 是真正 CLI 或其有效绝对路径。存当前模型、URL、非敏感配置和独立 credentialRef，不存 Key。 |
| Session.tool | 记录创建者，仅用于溯源，不直接决定后续执行入口。 |
| Session.family | 独立保留历史家族；旧记录从有效 AgentDef/内置表回填，无法可靠识别的自定义 Agent 不猜测。 |
| Session.lastCloneId | 记录上次实际打开的入口，首次从创建者初始化；删除回退见第 7 节。 |
| Session.nativeSessionId / resumable | 保留原生恢复语义；没有有效原生 ID 的记录仍不可继续。 |
| Session.profileId / launchPermission | 若保留，仅用于展示/诊断一次实际启动；不作为下次启动配置来源，会话不保存 Key。 |

分身配置的唯一权威来源是当前配置；设置、导入、顶栏、历史操作和系统 helper 都通过同一解析规则读取。创建者已删除时，原生能力从 family 取得，不能退入自定义 Agent 的通用 `--resume`。

### 5.2 历史身份与迁移

Claude/Codex 的规范关联键为 `family + nativeSessionId`；各家族默认目录只扫描一次。其他内置/自定义 Agent 保留自己的 tool 身份，不能把全部 Session 强制收窄为两个家族。

该身份必须贯通：原生 ID 自动发现、history IPC、关联/去重、详情、标题、别名、搜索、筛选计数和目录分页。现 TerminalView 向 historyFindRecent 传分身 tool 时，主进程按内置根查找会失败；只改卡片 key 不算完成。

迁移保留原生 ID、手动标题、来源关系和目录展开状态，并转换旧 alias 键。同一规范身份已有多条本机记录时，保留数据并确定唯一关联代表（优先已有活跃终端，否则最近实际打开记录）；所有重复项共用入口决定，不依赖数组首条，不静默删除 transcript。

新建/分叉的原生 ID 一对一认领，校验家族、cwd、启动时间、已占用 ID；fork 排除来源 ID。同目录 A/B 并发有歧义时保留未关联状态，不猜测最新文件。

系统启动器在 RingCode 外打开的记录没有可靠的入口归因；未关联时仍默认原版，不从命令名或日志猜 Key。

### 5.3 替代旧规格的范围

本规划替代《会话历史与恢复改造》第 4 节中 Claude/Codex 家族“继续本机会话优先保存 Profile/权限”的规则：**包括原版入口，后续启动都读取所选入口当前配置。** 原版沿用现有当前配置解析，分身固定一套全局配置；其他 Agent 原有规则不变。

继续仍复用原 RingCode Session。单击仅选择、详情按需读取、原生恢复/分叉、失败状态和替代目录流程沿用旧规格。目录分组、排序、30 条分页、搜索计数和展开状态遵循《历史会话目录分组》。

## 6. 启动行为

### 6.1 当前配置和统一校验

1. 顶栏、本机/磁盘继续、换入口、分叉及系统启动器共用配置解析和启动校验；会话只提供上下文、cwd 和默认入口。
2. 分身缺 Key、凭据读取失败或配置无效时停止启动，显示具体原因及补配置入口。主进程/helper 最终读取凭据时校验，不只信渲染层 credentialSet；原版无 Key 仍可 CLI 登录。
3. 新建 cwd 取当前工作区，继续优先历史目录；目录失效/不可访问时选择替代目录，取消不启动、不更新上次入口。
4. 经现有绝对路径解析执行真正 CLI；Windows cmd/bat 可走现有 cmd.exe 适配层，不依赖分身短命令或用户 PowerShell profile。
5. 启动时读取最新配置并冻结本次参数；改配置不改变运行中的进程，下次启动生效。

### 6.2 环境、模型和权限

主进程/helper 区分“删除环境变量”和“向指定变量注入密钥”。先清理父环境中会串用线路的凭据、URL、家目录覆写，再注入当前入口选择；密钥不进 argv、脚本、日志、会话或渲染层回读。

- Claude 分身默认：URL 空时清继承 BASE_URL/AUTH_TOKEN，仅注 ANTHROPIC_API_KEY；URL 非空时设置 ANTHROPIC_BASE_URL，清 API_KEY，仅注 ANTHROPIC_AUTH_TOKEN。设置可覆盖凭据变量，但每次只选一个注入目标，不把同一 Key 填入全部敏感变量。
- Claude Code 会用 `~/.claude/settings.json` 的 `env` **盖掉**进程注入的 `ANTHROPIC_*`。分身启动时写入 `~\.ringcode\claude-settings\<cloneId>.json`，并以 `--settings` 传入；不改用户主 `settings.json`。
- 分身清除父环境 CODEX_HOME / Claude 配置目录覆写，并阻止分身配置重新设置隔离目录，始终使用默认家目录。原版检测到会把历史写到默认目录外的设置时应提示目录冲突，不能把隔离目录静默当作默认扫描范围。
- Codex 分身按 family 使用与内置 Codex 相同的 WT_SESSION 滚动兼容处理。Codex 不走 settings.env，用 `--profile` overlay；原版 Codex 在 RingCode 内启动时另带 `ringcode-provider-alias.config.toml`，只定义 `[model_providers.ringcode-clone]`，不设顶层 `model_provider`，以便删除分身后仍能在 RingCode 内 resume 旧会话。不得把该 provider 写进用户主 `config.toml`，否则会影响 Codex 桌面版的官方模型目录。
- 当前权限选择是本次参数的唯一来源，旧 Session 权限和冲突 profile args 不能覆盖它。
- 自定义模型使用当前值；“CLI 默认”明确表示跟随 CLI 当前默认值，空模型不视为缺配置。创建/编辑分身可按当前 URL+Key 拉取模型列表（失败可手填）。

### 6.3 Codex profile 机制

官方文档说明 **Codex 0.134.0 起**，`--profile name` 在主配置之上加载 `~\.codex\name.config.toml`，文件使用顶层字段，不再从主配置 `[profiles.name]` 读取。最低支持该机制的版本；实现前记录实际可执行文件、版本和 new/resume/fork 行为。仅在 help 中找到 `--profile` 不足以确认兼容。

自定义线路结构示例（模型和 URL 必须取当前配置）：

```toml
model = "<当前自定义模型>"
model_provider = "ringcode-clone"

[model_providers.ringcode-clone]
name = "RingCode clone"
base_url = "https://gateway.example/v1"
env_key = "RINGCODE_CODEX_KEY"
wire_api = "responses"
```

- Key 由主进程/helper 注入声明的 env，协议及认证模式须与网关相容。URL 空时也要明确选择官方线路，避免继承原版自定义 provider；CLI 登录态不能静默替代分身指定 Key。
- profile 是叠加层。分身当前显式模型、权限通过受支持 CLI 参数确保生效；其他来源中的冲突参数须规范化或拒绝。系统策略/配置叠加导致不能满足选择时，明确报告限制。
- Codex 使用 `resume <id>` / `fork <id>`；分别验证 profile、模型和权限参数的位置与结果，不使用自定义 Agent 通用 `--resume`。
- profile 原子写入，检查文件归属，只改本应用所属目标文件；用户主 config.toml 不改，会话仍进默认 sessions。
- 旧版提示升级，不自动迁移主配置，不隔离 CODEX_HOME。

来源：[OpenAI 官方高级配置文档](https://learn.chatgpt.com/docs/config-file/config-advanced)，2026-09-11 评审核验。本机 Codex 0.153.4 overlay 已实测；删除分身后原版 resume 用 provider 别名 overlay。

## 7. 继续、换入口与分叉

### 7.1 入口选择

1. 本机取有效 lastCloneId；仅旧数据缺字段时参考创建者，再回退家族原版。已关联磁盘使用同一规则，未关联磁盘默认原版。
2. 入口存在但缺 Key 时要求补配置或主动改选，不偷偷换原版或借用其他 Key。
3. 入口已删除时回退家族原版并展示原因；同名重建不接管旧身份。历史日志/原生 ID 本身失效仍按不可恢复处理。
4. 同一本机/原生身份已有活跃终端时，继续激活它，换入口禁用并提示先结束；启动中的尝试也须防重复提交。

### 7.2 启动尝试与上次入口

一次启动持有独立 attempt id、待提交入口和本次元数据。主进程校验失败、目录选择取消、文件写入失败或 spawn 抛错不更新上次入口。

最低可观察提交点是主进程完成校验且 PTY 创建成功；这只能证明进程已打开，不能当成鉴权或原生恢复成功。实施前须验证目标 CLI 是否提供可靠的恢复就绪/启动失败信号。

明确的启动阶段配置、鉴权、恢复失败应标 failed，并撤回该次入口提交；仅当它仍为最新尝试才回滚，防止旧回调覆盖新操作。无法可靠区分时，在验证记录中说明“上次”只能保证进程打开语义；不得用任意延时或 TUI 文本猜测完整恢复成功，该兼容性结论须在发布前明确。正常运行后的任务错误不等于启动失败。

失败不自动打开空白会话，保留旧规格的重试/基于此新建入口。Session 的本次 profileId/launchPermission 如保留，随启动结果一致更新；后续启动仍读取最新配置。

### 7.3 基于此新建

本机和磁盘共用有效入口选择，默认上次打开的入口及当前配置。新 RingCode Session 记录所选入口、来源关系，并等待新的原生 ID；不修改来源会话上次入口。原生 fork 优先，上下文降级仍明确标为独立新会话。

## 8. 历史 UI

- 保留本机/磁盘 Tab、现有目录分组及家族筛选，不增加分身芯片。
- 本机及已关联磁盘显示“继续使用：分身名”；删除回退说明“原分身已删除，使用原版”，缺 Key 显示待补配置。
- 未关联磁盘不标创建分身，操作入口写“用原版继续”，可改选同家族入口。
- 活跃会话显示实际运行入口，继续激活现有终端；配置已改时不冒称该进程已切线路。
- 列表、详情、菜单使用同一身份、入口解析和禁用原因；分页计数保持一致。

## 9. 系统启动器与 PATH

### 9.1 执行契约

最终交付时创建分身即尝试生成 `%USERPROFILE%\.ringcode\bin\<命令名>.cmd` 或等价物；失败不挡顶栏，但显示“系统命令未生成”、原因和重试入口。

启动器绑定稳定分身 ID，通过随应用交付的 helper 读取当前非敏感配置和 Windows 凭据，GUI 关闭时也能运行。可用应用 CLI 模式或独立 helper，须验证安装路径变化、升级和卸载后的行为。

**不得写死创建时的 URL、模型和权限。** 每次读取最新配置，与顶栏一致；如需 helper 可读的派生文件，保持同一权威来源，使用版本和原子更新。配置读取失败时退出，不偷偷用旧线路。

缺 Key/凭据读取失败明确报错并非零退出。正确转发带空格参数、cwd、退出码和中断；转发 resume/fork 参数不能覆盖家目录和分身线路身份。内置终端的 WT_SESSION 与普通系统终端兼容行为分别验证。

### 9.2 PATH

不自动改 PATH。提供打开目录、完整启动器调用路径及用户级 PATH 设置指引；如提供 PowerShell 语句，只读取/追加用户 PATH，去重保留原内容，不用 `setx PATH "%PATH%;..."` 回写合并 PATH。

PATH 更新后让终端宿主刷新环境；通常重新打开终端，仍继承旧环境时退出重开宿主或 RingCode，无须重启电脑。顶栏不依赖分身 bin 加入 PATH，但基础 CLI 仍需通过既有 PATH 或明确绝对路径解析。

旧 PowerShell 函数/别名可能优先于启动器。现 where/which 不能保证发现任意现有会话函数，不为检测而执行用户 profile；创建命令名 `hjcodex` 时固定提示，提供 `Get-Command hjcodex -All` 人工诊断及完整路径调用方式。

## 10. 设置、删除与清理

### 10.1 设置及命令名

- 原版行提供复制分身；分身行提供编辑配置、清 Key、删除、打开目录和重试生成。密钥只显示设置状态。创建/编辑时可搜索或手填模型，也可「获取模型列表」（需 URL+Key；URL 空走官方。聊天基址若无 `/v1/models` 会回退打主机 `/v1/models`）。
- 命令名强制匹配 `[a-z][a-z0-9-]*`，限制合理长度；排除 Windows 设备名 con/prn/aux/nul/com1..9/lpt1..9，按大小写不敏感判重。
- 不占用内置或已有 Agent/分身命令；检查启动器和 profile 文件归属，已有非本应用文件不覆盖；PATH 其他命令重名提示警告。
- 显示名可改，第一版命令名固定；改命令名需新建分身，稳定 ID 和凭据引用不复用。
- 导入分身走相同校验，建立本机新身份和独立凭据引用；不直接信任外来 credentialRef，不绕过缺 Key/文件归属检查。

### 10.2 运行中检查

删除分身、单清其 Key 前，必须结束它在 RingCode 中全部运行中/启动中终端；全清前必须结束全部 RingCode AI 终端。显示涉及终端，用户自行结束后重试，不自动终止。

单清/删除提示关闭该分身外部会话，全清提示关闭全部相关外部会话。外部进程不承诺完全检测；删除本机凭据无法撤回已注入进程的 Key，也不等于服务端吊销。

### 10.3 清理范围与失败

| 动作 | Key | 启动器和分身 Codex profile | 分身设置 | RingCode 会话 |
| --- | --- | --- | --- | --- |
| 单清分身 Key | 删该引用 | 保留，启动时报缺 Key | 保留，标缺 Key | 保留，入口不变 |
| 删除分身 | 删该引用 | 删本应用所属文件 | 删全部关联 ToolProfile、权限及默认入口引用 | 保留，指向它的上次入口回退原版 |
| 一键全清 | 删 RingCode 所有凭据，含原版及遗留引用 | 仅删本应用所属文件 | 保留，分身标缺 Key；补 Key 后重建 | 保留 |
| 清本地数据 | 不动 | 不动 | 沿用现有本地设置重置 | 沿用本地记录重置 |

所有清理均不修改原生历史和用户主 config.toml。删除分身只恢复入口可选性，不保证已失效日志或登录状态能够恢复。

清本地数据会丢失配置及引用，因此需要不随重置消失的资源归属清单，或等效凭据枚举和文件归属机制。清单记录资源身份/路径及必要非敏感元数据，不另建可编辑配置体系。重置后仍能清到遗留资源；原启动器找不到配置时报错，不冒用同名新分身。

清理逐项返回结果：不存在视为幂等完成，失败保留待清理项和归属信息，支持重试，不宣告全清成功。全清后不后台重建；用户补 Key 时重建该分身资源，生成失败可显式重试。运行检查与清理/启动协调，避免检查后又并发启动。

5. A/B 同目录近同时新建、fork 回填及跨家族相同原生 ID 不串绑；歧义不猜测。
6. 删除 A 后旧会话仍可选择原版，同名重建不接管旧身份；无有效原生 ID 仍不可继续。
7. 本机/磁盘入口标签、回退/缺 Key 提示正确；详情、别名、标题、目录计数/分页/展开状态保持一致。
8. 迁移覆盖其他 Agent、旧 alias、重复本机关联、运行中快照和已删除 Profile，不丢原始数据。

### 12.3 删除、清理和启动器

1. 相关终端运行时删除/清理被阻止，全清提示关闭外部会话。
2. 删除分身清其所属配置/Key/文件，原生历史、主配置和其他分身保留。
3. 全清保留设置并标缺 Key，补 Key 后恢复命令；无操作时不后台重建。
4. 先清数据、重启再全清仍能找到遗留资源；部分失败可重试，不误报成功。
5. 设备名、大小写重名、用户已有文件、旧函数、导入重名/外来凭据引用按规则处理。
6. 生成失败不挡顶栏，原因及重试可用；GUI 关闭、安装路径/参数含空格、cwd、退出码、中断和配置更新验证通过。
7. 不自动改 PATH，短名及完整路径指引准确。

### 12.4 快速启动显示与收纳

执行第 15.7 节验收，覆盖显隐持久化、最多 4 个独立按钮、自动收纳、搜索列表和隐藏后的历史恢复。

代码实施阶段执行适配后的自动测试、类型检查、构建及 Electron/CLI 实机验收。自动测试与 typecheck 已再跑通（2026-09-14：49 files / 226 tests）。第 15.7 节窗口收纳已在 Electron 用 960/1024/1152/1440 实测。2026-09-14 用户确认 Claude/Codex 分身主路径实机通过。

## 13. 剩余技术验证与限制

- 官方 overlay 已在 Codex 0.153.4 用隔离 CODEX_HOME 的 `exec --profile` 证实：`$CODEX_HOME/<name>.config.toml` 顶层字段可覆盖 model/provider。缺失 profile 静默回退主配置。resume/fork 接受该参数。删除分身后原版 resume 依赖 `ringcode-provider-alias` overlay（只提供 `[model_providers.ringcode-clone]`）。RingCode 外直接 `codex resume` 或从 Codex 桌面版打开仍可能找不到该 provider；如需桌面版续聊，应另做官方 provider 会话副本/迁移，不能修改全局 provider 目录。
- PTY 创建、鉴权和原生恢复成功不等价；第 7.2 节采用「PTY 创建即提交、明确失败且为最新 attempt 才撤回」，不以等待几秒无退出代替确认。
- 默认家目录还会共享其他 CLI 原生状态；承诺分身 Key/URL/模型/权限选择独立，不承诺隔离插件、缓存等所有状态。
- 外部系统命令没有可靠的 RingCode 入口归因；清凭据无法撤回外部进程已有 Key。
- 自定义 Agent 的“移除”仍只删定义。分身删除与运行中拦截已 Electron 实测。**空闲一键全清未对真实家目录执行**（会扫 Windows 凭据与 `~/.ringcode`），不能当作第 12.3 节全清代跑通过。
- 系统 helper 通过 `%USERPROFILE%\.ringcode\app-launch.cmd` 以 `ELECTRON_RUN_AS_NODE=1` 调用 `electron-dist/cloneLaunchCli.js`。GUI 关闭缺 Key、cmd 转发带空格参数、cwd/中断/安装路径引号已测。
- 本机 Codex 0.153.4 满足 overlay 最低版本；启动路径尚未对更旧 CLI 自动提示升级。
- Claude 分身必须走 `--settings`；只注入进程 env 会被 `~/.claude/settings.json` 盖掉。
- 模型列表接口因网关而异：`/anthropic` 聊天基址常需回退主机 `/v1/models`；部分推理接口没有 OpenAI 式 `/models`，拉不到就手填。

## 15. 顶栏快速启动显隐与收纳（已确认）

> 用户已确认：设置控制 Agent 快速启动显隐与顺序，采用“常用按钮 + 更多列表”；隐藏同时作用于顶栏和更多列表。  
> 本节产品代码已实现；第 15.7 节窗口收纳已在 Electron 用 960/1024/1152/1440 与 1/4/5/20 入口实测。OS 125%/150% DPI 用收窄 CSS 视口代替，未改系统缩放。

### 15.1 现状与范围

现 TopBar 直接遍历 listAgents；窗口小于 1180px 时 CSS 隐藏文字，保留所有图标。分身复用家族图标后，仅凭图标难以区分，数量继续增加也不能保证顶栏放得下。设置目前只有权限和移除，没有显示偏好。

本节覆盖所有内置 Agent、自定义 Agent 和分身的**顶部 AI 快速启动区**，不局限 Claude/Codex；工作区、搜索、命令面板、布局、设置、主题等其他工具按钮不纳入本轮显隐设置。

显示偏好是界面设置，与 Agent 是否可执行、Key 是否齐全、会话恢复资格分开。按 Agent 稳定 ID 保存，不按名称或 family 一起隐藏；隐藏原版不会隐藏它的全部分身。

### 15.2 布局：常用按钮 + 更多列表

常用入口保持一键启动，其余放入可搜索列表。第一版不增加“按钮/列表两套模式”的切换选项。

```text
正常宽度： [Claude Code] [Codex] [便宜版 Codex] [更多（3）▾] [设置]
较窄窗口： [Claude Code] [Codex] [更多（4）▾] [设置]
仅够列表： [启动 Agent ▾] [设置]
```

示例表示可见数量由实际空间决定，不保证某分身永远固定在示例位置。

- 先按用户显示开关筛选，再按用户顺序排列。顶栏最多直接展示 4 个，其余进入“更多”；4 是第一版布局上限，不是 Agent 数量上限，不增加数量设置。
- 实际可用宽度不足时，从序列末尾逐个收纳，优先保留排在前面的入口；预留“更多”、设置等既有控件空间。若全部能放下且数量不超过 4 个，不显示空“更多”。
- 收纳依据启动区实际宽度，考虑工作区长名称、按钮名称、字体和窗口缩放；不只依赖一个视口断点。
- 保留“图标 + 名称”，长名省略并可查看完整名，不退化成一排相同家族图标。不要双行换行或横向滚动顶栏，也不能把设置按钮挤出窗口。
- 极窄可用区收成一个“启动 Agent”列表入口；该列表包含所有设为显示的 Agent。空间恢复时按原顺序恢复按钮，不持久化收纳结果。
- 自动收纳不改用户开关，不按最近使用/是否缺 Key 自动洗牌，避免按钮位置跳动。

### 15.3 设置 → Agent

沿用现 Agent 管理页；在每个 Agent 行增加“快速启动中显示”开关，并提供上移/下移调整启动顺序。可以按需加拖动手柄，但上移/下移及键盘操作必须可用，第一版不依赖拖拽。

```text
快速启动（显示开关同时作用于顶栏和“更多”）
Claude Code       [显示 开]   [上移] [下移]
Codex             [显示 开]   [上移] [下移]
便宜版 Codex      [显示 开]   [上移] [下移]
Hermes            [显示 关]   [上移] [下移]
```

- 设置始终列出全部有效 Agent，隐藏项也保留，方便重新打开；显示开关即时生效、持久化、重启保留。
- 解释文案：“隐藏后不出现在顶部快速启动区，仍可通过历史、命令面板和快捷键使用。”开关不是停用或卸载。
- 提供“恢复默认显示与顺序”，只重置本节偏好，不改 Key、权限、默认工具或历史。允许全部隐藏，不强迫至少保留一个。
- 全部隐藏时整个 AI 启动区收起，保留现有设置按钮及命令面板，不偷偷恢复某个 Agent。用户从设置重新打开即可。
- 设置行过多时可按显示名/命令名搜索；顺序变更仍针对完整序列，搜索不改永久顺序。

### 15.4 更多列表

- 正常情况下“更多（N）”只列本次溢出的 N 个入口；设为隐藏的 Agent 不出现。没有任何独立按钮时，名称改为“启动 Agent”，列全部设为显示的入口。
- 使用单层列表，按启动顺序排列；不做家族多级悬浮菜单。每行显示图标、显示名和命令名/家族辅助说明，确保同名或相同图标的分身可区分；不展示 Key 或完整私有 URL。
- 列表提供搜索，匹配本列表中的显示名、命令名、家族，大小写不敏感；空结果显示清除搜索入口。数量多时限定面板高度并纵向滚动，不让菜单超出窗口。
- 点击可用行即调用现有统一启动动作，用当前工作区和当前配置新建会话；不先跳设置，也不混入恢复旧会话的动作。
- 缺 Key、未安装 CLI等状态只影响可用性，不自动隐藏。已知不可用项标原因并提供“去配置/查看原因”；主进程仍执行最终校验，UI 缓存状态不替代它。
- 列表底部提供“管理快速启动”，打开设置 Agent 页对应区域。启动、转设置、点击外部或 Escape 后关闭面板。
- 按钮可由 Enter/Space 打开，搜索框有明确名称，方向键导航结果、Enter 执行、Escape 关闭，焦点清晰。关闭后焦点回触发按钮；触发按钮因显隐/窗口变化消失时回到有效替代入口或设置按钮。不能只靠 hover 操作。

### 15.5 隐藏与分身行为的边界

| 操作/状态 | 规则 |
| --- | --- |
| 隐藏 Agent | 顶部独立按钮和更多列表都隐藏；配置、凭据、系统启动器、命令面板及快捷键保留。 |
| 隐藏正在运行的 Agent | 仅隐藏快捷入口，不结束终端，不阻止历史继续。 |
| 上次入口已隐藏 | 继续仍使用它的最新配置；“换一个”仍列出全部同家族入口，隐藏不触发原版回退。 |
| 隐藏默认工具 | 不改默认工具，也不改既有快捷键；显示策略不承担禁用工具的职责。 |
| 删除分身 | 按第 10 节清理，同时移除对应显示/排序偏好；已打开列表立即移除该项，执行前再校验它仍存在。 |
| 新建/复制分身 | 默认显示，追加到现有启动顺序末尾，不继承来源的隐藏状态；放不下进入更多，不挤占已有顺序。 |
| 全清 Key/启动器 | 保留显示与排序偏好，分身显示缺 Key，不因清理重新洗牌。 |
| 清本地数据 | 随本地设置重置显示偏好；密钥/历史边界仍遵循第 10 节。 |

隐藏只解决不常用入口占位；若将来需要全面禁用某工具，应单独设计，不能复用显示字段。

### 15.6 数据与旧数据兼容

建议在 AppSettings 增加 quickLaunch.hiddenAgentIds 与 quickLaunch.agentOrder（字段名可调整），保存稳定 ID。自动溢出集合及搜索词属于临时 UI 状态，不持久化；不把显示字段放进 Session 或 ToolProfile。

- 旧快照无字段时：所有有效 Agent 默认显示、按现有 listAgents 顺序，超出宽度/数量的进入更多，不丢入口。
- 顺序中重复/无效 ID 去重过滤，未列入的有效 ID 按现有顺序补到末尾；隐藏集合不因菜单搜索或窗口变化被重置。
- 普通配置导入不覆盖现有显示偏好；新导入 Agent 使用新身份，按新增规则处理。未来若支持导入界面偏好，必须映射身份并校验。
- 不从 listAgents 全局删隐藏 Agent，否则会破坏命令注册、历史筛选、恢复选项及设置管理。单独派生快速启动展示清单，复用统一启动校验。
- 本节是对 requirements AIT-001“并列入口”的显示扩展；原版可以被用户隐藏或因空间进入列表，启动能力保留。
