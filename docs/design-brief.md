# 金刚琢 设计稿 Brief

> 依据：`docs/requirements.md` v0.2
> 用途：交互与视觉设计的输入依据（2026-08 草案），先出线框图过流程，再出高保真。
> 实现对照（2026-09-15）：本文不是当前 UI 清单。树形文件管理、终端分屏、并排预览已落地。启动流程改为点入口即启动，无 LaunchModal。顶栏是最多 4 个具名入口 +「更多」，含分身；Claude/Codex 历史可改选同家族原版或分身继续。文件树菜单是「把路径插入当前终端」，拖入终端走拖拽，不是单独菜单项。设置含「关于与更新」；应用启动后及每 4 小时检查 GitHub Release，发现新版时展示更新说明并可在应用内下载安装。当前交互以代码和 `docs/进度.md` 为准。
> 目标平台：Windows 10 (1809+) / 11 x64 桌面端，键鼠为主，需兼顾高 DPI 缩放。
> 实现说明（2026-08-15）：布局可用自制 Splitter 过渡，嵌套分屏仍按 TRM-004 为 P0。文件管理器若先做导航式浏览，FIL-001 的树形展开/折叠仍是需求，不是降级。Git / PDF 按 P1 出稿并标注「v1.0」。

## 1. 设计范围

MVP 需要覆盖的主界面与流程。P1 功能可出稿但标注「v1.0」，不阻塞 MVP。

主界面四区结构见 requirements 5.1：顶部工具栏 / 左侧栏 / 中间主区域（上编辑器、下终端）/ 右侧栏。所有区域可拖拽调尺寸、隐藏、最大化，重启恢复布局。

## 2. 关键流程线框图（先出低保真）

下列流程需画完整页面流转，含分支与失败路径：

1. **首次启动向导**：欢迎页（说明本地数据位置）→ 环境检测（Windows/PowerShell/Claude Code/Codex，逐项显示状态）→ 选第一个工作区 → 进入主界面。含「工具未检测到」分支（显示路径 + 重新检测 + 手动配置入口，不自动安装）。
2. **启动 AI 会话**：点顶部 Claude Code 或 Codex → 读工作区默认配置方案 → 启动前确认面板（工具/工作目录/配置，敏感变量掩码）→ 创建专用终端 + 新会话记录 → 右侧显示会话信息、历史列表出现新项。含「启动失败」分支（终端保留错误 + 重新运行 + 打开配置）。
3. **历史会话搜索与继续**：打开历史面板 → 关键词搜索 / 按工具·工作区·日期筛选 → 选中查看文本记录 → 「继续会话」（可恢复）或「基于此记录新建」（不可恢复，明确提示差异）。含「会话已中断」「恢复失败」状态。
4. **Skill 导入与管理**：从本地文件夹导入 → 计算内容指纹 → 库中显示名称/来源/作用域/指纹/更新时间 → 查看/搜索/管理。MVP 不画兼容判断与同步。
5. **文件编辑 + 预览**：左侧选 Markdown → 中间编辑 → 右侧实时预览（随保存或输入更新）。含「外部修改且本地有未保存内容」冲突提示。
6. **布局调整**：拖拽调尺寸 / 隐藏 / 临时最大化各区域；编辑器、终端、右侧面板标签页切换。
7. **命令面板**：快捷键唤起 → 模糊搜索命令 → 执行。

## 3. 状态矩阵

每个主区域必须设计「空 / 加载 / 错误 / 无结果」四态，不要只画正常路径：

| 区域 | 空状态 | 加载 | 错误 | 无结果 |
| --- | --- | --- | --- | --- |
| 文件树 | 工作区为空 / 未打开工作区 | 读取中 | 无权限、路径不存在 | 搜索无匹配 |
| 编辑器 | 无打开文件 | — | 外部修改冲突、保存失败、文件过大 | — |
| 终端 | 无终端（引导新建） | — | 启动失败、进程异常退出 | 查找无匹配 |
| 历史列表 | 无历史（引导首次启动） | 搜索中 | 会话已中断、恢复失败 | 搜索/筛选无结果 |
| Skill 库 | 无 Skill（引导导入） | 导入中 | 导入失败、指纹重复 | 搜索无匹配 |
| 全局 | — | 启动/检测中 | 工具未检测到、更新检查失败 | — |

## 6. 视觉规范（设计 token）

所有视觉属性以 token 组织，主题 = 一套 token 取值的集合。首版交付浅色和深色两套主题；架构上要求新增主题只需新增一套 token 取值，不改组件代码，且用户可在设置中切换。具体要求：

- **色彩**：主色、语义色（成功/警告/错误/信息）、中性色阶（背景/表面/边框/文字层级）；每套主题独立给出一组取值
- **字体**：UI 字体、代码等宽字体（与 Monaco 一致）、字号阶、行高
- **图标**：图标库选型、尺寸规范（16/20/24）、可访问名称
- **间距**：基础栅格（建议 4/8）、组件内/外间距
- **形态**：圆角、阴影、边框、焦点环（满足对比度与可访问性）
- **缩放策略**：100%/125%/150%/200% Windows 缩放下的尺寸与布局处理（UI-005）

## 7. 文案语气规范

- 术语统一：工作区、会话、配置方案、Skill、终端、工具适配器。
- 按钮：动词开头，简洁（「启动」「继续会话」「基于此记录新建」）。
- 错误：先说原因，再给建议（「Claude Code 启动失败：<原因>。可重新运行或检查配置。」）。
- 确认：说明影响范围（「关闭此终端将终止正在运行的进程」）。
- 敏感信息：凭据只显示「已设置」+ 掩码，不显示明文。

## 8. 技术约束（影响可行性，务必告知设计师）

- 框架：Electron + React + Vite + TypeScript。
- 编辑器是 **Monaco**，终端是 **xterm.js + ConPTY**：两者是现成组件，主题色和外壳可定制，但内部渲染结构难以大改，不要画「终端内嵌自定义富 UI」之类实现不了的稿。
- 布局用成熟 **Dock/Panel 库**：嵌套分屏、状态持久化由库提供，设计需顺应其能力，避免无法实现的自由布局。
- 高 DPI：100%~200% 缩放下不得出现重叠或不可操作（UI-003/005，发布阻断项）。
- 键盘可达：核心操作必须键盘完成（10.4）。
- 本地优先、无云端：不画需要服务端的功能（协作、市场、云同步均非 MVP）。
