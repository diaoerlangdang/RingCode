## 1. 目标与范围

本规划分阶段解决以下日常使用问题。本次 v0.4.7 只实施第 1、2 项；第 3～5 项保留为后续阶段：

1. Markdown 中的 Mermaid 图表目前只显示源码；长文档缺少按标题跳转的目录。
2. 编辑和预览区域较小时，长文档与较大的图表不便查看。
3. 终端滚动到历史输出后，看不到 CLI 原有输入区。
4. 截图粘贴到 CLI 不便，缺少发送前的图片预览和管理。
5. Ctrl+C 容易被终端解释为中断或退出，希望复制与中断分开。

完整规划采用：**Markdown 图表与目录增强 + 应用内面板最大化 + 原生终端旁的固定底部输入区 + 本地图片缓存与路径引用 + 明确的复制和中断操作。**

## 2. 已确定的产品决策

| 项目 | 本版决定 |
| --- | --- |
| Markdown 渲染 | 保留现有 marked，增加 Mermaid，不更换整套编辑器 |
| 导航含义 | 文档内部按标题跳转的目录，不是多文件文档导航 |
| 参考对象 | 参考 Yank Note 的目录、图表和阅读体验，在现有项目内实现 |
| 目录交互 | 层级展示、点击跳转、当前章节高亮、可收起 |
| 全屏含义 | 先做应用内编辑器/预览面板最大化，再还原原布局 |
| 终端方案 | 增加独立底部输入框，上方保留原生终端 |
| 图片方案 | 粘贴后保存本地副本并显示缩略图；本版优先以路径引用交给 CLI |
| 发送时机 | 文本和图片先进入草稿，用户主动发送，粘贴不自动发送 |
| Ctrl+C | 新输入框内用于复制，不向 CLI 传递中断字符 |
| 终端复制 | 增强输入模式下，有选区复制；没有选区不发送 Ctrl+C |
| 中断 | 提供独立“中断任务”按钮，与关闭终端区分 |
| 图片保留 | 已发送图片跟随会话保留，关闭终端和退出应用不触发删除 |
| 图片清理 | 仅清理应用创建的缓存副本；用户原始图片不删除 |

### 2.1 首版适配范围

- 优先验证 Claude Code、Codex 及其分身；分身沿用所属家族的输入处理。
- 其他 AI CLI 的原生终端继续可用。底部输入框的发送和图片引用能力须按工具验证，不能默认宣称全部兼容。
- 普通 PowerShell 是否启用同样的底部输入框尚未明确。本版建议先覆盖 AI 会话，普通 Shell 保持原有交互。
- 以上适配范围是实施建议，不应把尚未验证的 CLI 能力写成已支持。

## 4. Markdown 图表与标题目录

### 4.1 Mermaid

- 识别带 `mermaid` 语言标记的围栏代码块，绘制流程图、时序图等 Mermaid 支持的图表。
- 普通代码块保持现有展示方式，不把无标记代码自动猜测成图表。
- 图表随当前深浅主题变化，保持文字、连线与背景可辨认。
- 图表过宽时在图表区域内滚动，不撑破整个布局。
- 编辑过程中暂时无效的语法只影响当前图块，显示错误和源码，不影响正文、目录或其他图表。
- 按需加载图表依赖；异步渲染必须丢弃旧文件、旧内容的结果。

沿用现有不执行不受信任脚本的要求。不能为接入图表全面放开原始 Markdown 中的 script、iframe 或事件属性；需要明确图表生成的 SVG 与样式如何安全插入。

### 4.2 文档标题目录

- 从文档标题生成层级目录，支持 H1～H6。
- 目录与渲染正文使用同一份解析结果，避免正则误把代码块中的 `#` 当作标题。
- 支持中文、重复标题、标题内代码与强调；锚点唯一，能正确定位对应标题。
- 点击目录只滚动当前预览正文，不滚动整个应用。
- 随正文滚动高亮当前章节；目录本身可以独立滚动和收起。
- 无标题时显示简洁空态，不占用大块空白区域。
- 目录放在预览面板内。并排模式下默认收起，单独预览时可以展开。
- 目录按钮和条目支持键盘操作，并有可见焦点。

### 4.3 保留现有行为

单独预览和并排预览均须生效；本地相对图片解析、外部文件更新、未保存编辑、现有 HTML 清理以及非 Markdown 文件预览继续正常工作。图表或本地图片加载完成后，不应无故重置正文滚动位置。

本版不加入编辑器与预览双向同步滚动。图表和图片高度变化会增加映射复杂度，留待后续单独规划。

## 5. 编辑器与预览面板最大化

- 编辑器、预览工具栏提供“最大化 / 还原”按钮。
- 单独编辑或预览时，当前面板占满应用内容区，保留明确的还原入口。
- 并排模式可以分别最大化编辑器或预览，再恢复原并排布局。
- 进入前记录布局；还原后恢复侧栏显隐、区域比例和并排状态。
- 保留当前文件、未保存内容、Monaco 光标/选区和预览滚动位置。
- 最大化预览时仍可使用标题目录。
- 最大化状态建议作为临时状态，不覆盖用户原本保存的常规布局。

**生命周期约束：仅改变其他区域的可见性和布局，不能卸载正在运行的终端。** 当前 `TerminalView` 的卸载清理会销毁 PTY，因此不能直接复用可能卸载终端的布局分支。

若增加 Esc 还原，应优先让编辑器补全、搜索、弹层等处理自己的 Esc；不得把全局 Esc 转发成 CLI 中断。快捷键是否加入及具体按键在实施时结合冲突情况决定，按钮是本版必需入口。

本版不加入操作系统级无边框全屏，也不扩展到所有面板的最大化。

## 6. 固定底部输入区

### 6.1 布局与草稿

- 每个 AI 终端有自己的底部输入区：图片附件区、多行文本框、发送按钮、中断任务按钮。
- 输入区处于终端滚动容器之外，固定在当前终端面板底部。
- 上方继续显示原生 CLI 界面及滚动历史。CLI 自绘输入区仍可能出现，本版不通过裁切或正则隐藏它。
- 输入框随内容增长到合理高度，超过后在输入框内部滚动，避免挤掉全部输出空间。
- 切换终端分别保留草稿和图片；分屏中两侧分别显示目标终端，发送不依赖全局激活 ID。
- 编辑草稿不改变上方历史滚动位置。用户阅读历史时，新输出不强制拉回底部，并提供“回到最新”入口。
- 本版建议主动发送后回到最新输出，方便观察 CLI 接收结果。

### 6.2 输入规则

| 操作 | 行为 |
| --- | --- |
| Enter | 发送当前草稿 |
| Shift+Enter | 换行 |
| 中文输入法确认 | 完成组词，不误发送 |
| Ctrl+V / 图片拖入 | 加入草稿，不发送 |
| Ctrl+C / Ctrl+X / Ctrl+Z | 输入框内保持普通复制、剪切、撤销行为 |
| 编辑器插入所选/路径 | 启用增强输入时进入目标终端草稿 |
| 文件路径拖入 | 在增强输入模式下进入草稿，沿用路径处理规则 |

粘贴和拖拽事件需要区分输入框与原终端，避免父级捕获事件抢走输入框的原生编辑操作。

### 6.3 发送与原终端协作

- 复用现有多行粘贴保护和 Codex 换行适配，不使用“文本加回车直接写入 PTY”替代完整发送流程。
- 发送必须绑定确切终端实例，经现有输入链更新会话活动、原生会话关联等状态。
- 区分把文本交给终端与 CLI 确认收到了提问；前者不能被当成 Agent 已理解或执行的确认。
- 进程未就绪、已退出、孤儿终端或多行粘贴被阻止时，给出反馈并保留草稿/附件。
- 授权确认、方向键菜单、补全等仍在原终端操作，提供清晰的原终端操作入口。
- 不支持的 CLI 可以退回原终端输入；不能为了发送便利而跳过其授权流程。

当前会话状态只有 running/ended/interrupted/failed，并不能判断 CLI 正在等待提问、授权还是菜单操作。实施前必须验证：原终端已有未提交文字、CLI 工作中、确认菜单打开时如何避免拼接草稿或误提交。不能以进程 running 作为“可以安全发送提问”的依据。

## 7. 图片附件与路径引用

### 7.1 用户流程

1. 用户截图或复制图片，在底部输入框按 Ctrl+V；也可拖入图片或通过选择文件入口添加。
2. 应用保存受控缓存副本，并展示缩略图。支持多张图片、查看大图和发送前移除。
3. 用户填写问题；图片与文字共同留在草稿中，复制其他内容不会覆盖已有图片。
4. 用户发送时，应用附带明确的图片文件引用与读取说明，按目标 CLI 的输入处理发送。
5. 必须验证 Agent 实际读取并能描述图片内容，不能以显示缩略图或写入路径作为成功依据。

本版采用路径引用方式，例如“请读取并分析以下图片：<缓存路径>”，不宣称它是 CLI 的原生图片附件。

### 7.2 保存与访问

- 复制剪贴板图片时保存为 PNG，默认不缩放、不作有损压缩。
- 拖入或选择图片时管理应用副本，保留用户原文件；本版不进行图片编辑、裁剪或自动压缩。
- 缓存文件使用应用生成的唯一身份，避免依赖用户文件名拼接任意路径。
- 图片保存、读取和清理由主进程通过受控入口处理，不向渲染层开放任意文件系统访问。
- 缓存位置必须同时满足应用管理范围和 CLI 实际读取权限，不修改 CLI 沙箱或绕过权限检查。
- 建议优先评估既有 `ringcodeHome` 下的附件目录，避免污染项目；若 CLI 无法读取，另评估工作区内受控目录。
- 最终缓存根目录须在真实 Claude/Codex 权限模式下验证后确定。不能为读取缓存而把整个用户目录加入工作区白名单。
- 发送中路径带中文、空格等情况须验证；附件路径属于提示内容，不应被误解释为 Shell 命令。

### 7.3 会话关联

缓存副本需要记录其身份、受控存储位置、所属草稿/会话及删除状态。字段与存储位置沿现有持久化方式最小扩展，不另建通用资源平台。

- 附件创建和引用更新必须协调，启动时等待存储加载完成后才判断“无引用”。
- 草稿恢复策略要与附件引用保存保持一致，不能在重启后把仍属于草稿的图片误判为孤儿。
- 原版与分身切换不删除所属会话图片。
- 新会话或分叉若复用缓存图片，必须登记引用；共享副本只在没有其他引用时删除。
- 本版不承诺把图片附件复制到所有原生历史导出格式，也不写入各 CLI 内部数据库。

## 8. 图片清理规则

| 状态或动作 | 规则 |
| --- | --- |
| 从未发送的草稿移除图片 | 释放草稿引用；若无其他引用，删除缓存副本 |
| 已发送，所属会话仍保留 | 保留缓存副本，供后续引用与历史恢复 |
| 关闭终端、退出应用、进程退出 | 不视为删除会话，不清理已发送图片 |
| 会话收藏或暂时不再使用 | 不自动清理其仍有引用的图片 |
| 删除会话 | 释放会话引用；仅删除无其他引用的应用副本 |
| 删除失败 | 记录待删除状态，后续检查重试，不把失败当成完成 |
| 崩溃留下无引用文件 | 启动检查后进入宽限期，再清理；具体宽限期为实现参数，尚未确定 |
| 手动清理 | 显示占用空间；默认清理无引用缓存，保留被会话引用的附件 |

清理必须验证最终目标位于受控附件根目录内，只删除应用管理的副本，不删除用户原图。先核对引用，再删除文件；不能只按文件修改时间批量清理。

已有本地数据清理入口需要衔接附件引用和副本；活跃终端仍可能使用的图片不能被顺带清理。现有正文保留天数也不能直接作为图片删除依据。

本版提供附件占用空间和手动清理入口；不增加按天删除仍有会话引用图片的策略。

## 9. Ctrl+C 与中断操作

| 场景 | 增强输入模式行为 |
| --- | --- |
| 新输入框内选中文字后 Ctrl+C | 普通复制，不传给 PTY |
| 新输入框内无选区 Ctrl+C | 无操作，不传给 PTY |
| 原终端输出有选区 Ctrl+C | 复制选区，不中断 |
| 原终端输出无选区 Ctrl+C | 不发送中断字符 |
| 点击“中断任务” | 根据 CLI 家族发送经过验证的取消操作 |
| 关闭终端 | 沿现有关闭流程处理进程与确认，和中断区分 |
| 退出增强模式，使用原终端输入 | 恢复原生按键语义，并明确模式切换 |

复制行为不能只依赖 xterm 默认处理；目前自定义按键逻辑没有将 Ctrl+C 改为复制。

中断按钮不得直接调用销毁 PTY。各 CLI 的取消按键和状态语义不同，必须分别验证；例如连续发送 Ctrl+C 可能退出某些 CLI。应用不能承诺所有 CLI 的一次取消操作都不会结束会话。

本版不预设新的全局中断快捷键，避免与编辑器和 CLI 快捷键冲突。

## 10. 本版不包含的内容

- 多 Markdown 文件之间的文档站导航。
- 公式、PlantUML、Drawio、ECharts、可运行代码块、插件系统或整套 Yank Note 功能移植。
- 编辑器与预览双向同步滚动。
- 操作系统级全屏、所有区域的通用最大化系统。
- 裁切或识别 CLI 自绘输入区，替换原生 CLI 为完整聊天界面。
- Codex App Server、Claude 结构化会话协议或 SDK 的正式接入。
- 所有 CLI 的原生图片附件提交。后续可增强，用户侧粘贴与缩略图操作保持一致。
- 图片编辑、图片云上传、原生历史图片迁移或通用附件平台。

## 11. 实施顺序与验收标准

所有实施步骤均须在用户明确下达实施指令后启动。

### 阶段 A：Markdown 图表与目录

实施：在实际 `PreviewPane` 调用链中加入 Mermaid 和标题目录，调整独立滚动布局。

验收：

- 单独和并排预览均可显示流程图、时序图；普通代码块保持原样。
- 中文及重复标题跳转准确，代码块内伪标题不进入目录。
- 当前章节高亮正确；主题切换、坏图表、快速切换文件不造成错图或整篇失败。
- 本地相对图片、外部文件刷新和非 Markdown 预览无回归。

### 阶段 B：编辑器与预览最大化

实施：增加按钮与临时最大化状态，保持编辑器和终端生命周期。

验收：

- 单独编辑、单独预览、并排两侧均能最大化并还原。
- 布局、光标、未保存内容与滚动位置恢复。
- 最大化期间正在输出的 CLI 继续运行，还原后进程身份和输出历史保持。

### 阶段 C：底部输入框与复制/中断

实施：每终端草稿、统一插入路由、多行发送、Ctrl+C 和中断按钮。

验收：

- 浏览历史时输入框始终可见，编辑不改变输出位置；新输出不抢走历史阅读位置。
- Enter/Shift+Enter 与中文输入法正确，长文本和多空行不会误发送多次。
- 切换和分屏不串草稿、不串发送目标；插入所选和路径进入正确草稿。
- 复制不会终止或中断 CLI；原终端操作模式仍能处理授权、菜单、补全。
- 发送失败保留草稿，中断按家族验证，不以杀进程替代取消任务。
- 原终端已有草稿或处于确认界面时，不误提交或拼接错误内容。

### 阶段 D：图片缓存、发送与清理

实施：剪贴板图片、拖入/选择、缩略图、本地引用、会话关联、占用空间和清理入口。

验收：

- 截图、多图、中文和空格路径均可处理；发送前预览和移除可用。
- Claude Code、Codex 及分身真实读取图片并能回答图中内容，不能只验证路径已发送。
- 未授权/不可读取时有明确反馈，不静默丢图、不自动改变权限。
- 关闭终端、退出重启、恢复会话后图片仍可用。
- 删除无共享引用的会话副本会清理；共享引用、用户原图和受控根目录外文件保持安全。
- 待删除重试和孤儿宽限期生效；加载持久化之前不进行错误清理。

### 最终检查

- 按改动范围补充必要的行为回归测试，不为纯样式改动编写镜像测试。
- 执行 `npm run typecheck`、相关测试与构建检查。
- 用真实 Electron、Claude Code 和 Codex 完成上述关键交互验证；Web Mock 不能替代 CLI 图片和中断验证。
- 检查深浅主题、分屏、窄面板和 Windows 125%/150% 缩放。
- 实现验证完成后再更新进度文档。版本号、打包、提交和发布不属于本次规划工作。
