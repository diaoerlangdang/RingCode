# 终端输入增强：实现与验收记录

日期：2026-10-12。基线提交：`4c64359`（v0.4.7）。依据用户“开始剩下问题修复吧”实施规划中的 C/D 阶段。

当前状态：v0.5.0 用户验收通过。用户于 2026-10-13 授权提交、推送、打 tag，并自行创建 GitHub Release；本轮进入正式打包与发布准备。旧的 v0.4.7 安装包不包含本轮改动。

## 已实现

- Claude Code、Codex 与所属分身，以及 Antigravity CLI、OpenCode 使用底部独立输入框；普通 Shell、Hermes、其他自定义 CLI 和 Web Mock 保留原生输入。
- 每个终端独立保存文字和图片草稿；切换、分屏和窗口重载保留各自内容。插入所选、文件路径与拖入路径进入对应草稿。
- 输出滚动与输入区分离；提供“回到最新”。输入/发送按钮不随输出滚动，支持窄面板及 125%/150% 缩放。进入原生操作时收起底部草稿，给菜单留出空间。
- Enter 发送、Shift+Enter 换行；中文输入法确认不触发发送。发送绑定确切 PTY 实例，检查空提示、菜单、工作状态和原生输入；失败保留草稿。
- 先粘贴、等待 CLI 重绘，再核对输入内容，最后发送一次 Enter。CLI 将图片路径转换成图片标签时也能核对；未知界面保留草稿并转到原生操作。
- 增强模式下 Ctrl+C 复制终端选区，无选区不发送中断字符。输入框遵循普通复制行为；“中断任务”发送一次 Esc，不销毁 PTY。
- Ctrl+V 截图、拖入或选择 PNG/JPEG，每张最多 10 MB；显示缩略图，可放大查看、发送前移除。原图保持原样。

## CLI 兼容处理

Claude 支持 `❯` 与 `>` 提示符，并识别无颜色环境中的初始示例提示。RingCode 启动的 Claude 进程设置 `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false`，避免其后续建议与底部草稿冲突；不改 CLI 全局配置。该进程级开关来自 [Claude 官方说明](https://code.claude.com/docs/en/interactive-mode#turn-prompt-suggestions-off)。

Windows Codex 的控制台输入会吞掉裸 LF；CRLF 又可能提前提交。底部发送使用 Win32 Shift+Enter 按键事件保留换行与空行，Enter 单独提交。保留原有 `WT_SESSION` 兼容变量。Win32 事件格式参考 [Microsoft 的 ConPTY 输入说明](https://github.com/microsoft/terminal/blob/main/doc/specs/%234999%20-%20Improved%20keyboard%20handling%20in%20Conpty.md)。

Windows Codex 中的 Tab 会触发 CLI 快捷键，本轮阻止包含 Tab 的底部发送，并明确提示改为空格；不静默改变原文。`/` 命令和 `!` Shell 模式通过原生终端操作。

## 图片存储与清理

缓存位于 `app.getPath('userData')/attachments`，与当前 SQLite 数据库一起定位。采用这个位置而非独立的 `.ringcode` 目录，使引用快照和缓存随同一用户数据实例使用；不会将整个用户目录加入工作区白名单。

- 主进程生成 UUID 文件名，限制格式、大小、解码和路径；渲染层按图片 ID 读取，发送路径由主进程返回。
- 引用来自 SQLite 中的会话 `imageIds` 与终端 `terminalDrafts`，清理不依赖尚未加载的 UI。自动发送前等待引用持久化；已粘贴后转到原生模式手动提交的图片也登记会话引用。
- 发送过的图片跟随会话保留；关闭终端、退出应用、重载不会删除会话图片。分叉继承引用，共享副本要等所有引用释放后才删除。
- 移除草稿图片、关闭未发送草稿、删除会话时释放相应引用；删除会话先关闭关联进程。只删除无其他引用的受控副本。
- 崩溃留下的无引用副本有 24 小时宽限期；启动检查和设置中的手动清理遵循该规则。
- 删除失败的 ID 持久化到 `pending-delete.json`；下次检查重新核对引用并重试。损坏快照、无效路径和符号链接不会导致范围外删除。
- 设置显示图片数量、总空间和无引用空间；清除本地数据前需要关闭终端，再释放图片引用和缓存。

## 用户验收重点

1. 在自己的 Claude/Codex 分身、网关和权限配置下，粘贴截图、查看大图并发送问题；某些模型或网关可能没有图像能力。
2. 滚到历史输出后编辑草稿、切换和分屏，确认输入框始终可用，目标不会串线。
3. 目录信任等确认菜单出现时，用 ↑ / ↓ 选择、Enter 确认、Esc 取消；结束后底部草稿恢复可用。未识别的菜单仍通过“原生终端操作”完成。复制选区与单次中断分别验证。
4. 关闭/恢复会话、删除共享会话以及设置清理，确认原图和仍有引用的缓存保留。

分身复用家族发送逻辑；未逐一调用用户的所有独立网关配置。真实 CLI 与用户配置存在版本差异时，保留原生终端入口，不把“写入 PTY”当作 Agent 已理解图片的确认。

## 2026-10-13 真实 Claude 继续会话：滚轮失效定位

用户复测：继续会话后没有滚动条，底部输入模式与原生模式均无法用滚轮浏览历史；PageUp 可以翻到旧记录。前一轮组件模拟回放没有覆盖 Claude 的虚拟历史渲染，不能据此前的通过结果宣称该用户问题已解决。

状态：**原因已定位，修复方案待讨论；尚未更改 CLI 渲染/启动配置。** 本轮仅添加开发环境只读诊断，未终止当前 Claude 进程或发送模型任务。

证据：

- 对用户现有窗口采集只读元数据：底部模式显示 17 行，缓冲区也只有 17 行，`baseY=0`；原生模式显示 23 行，缓冲区也只有 23 行，`baseY=0`。两者 `scrollHeight=clientHeight`，没有终端历史滚动范围。
- 实际滚轮事件到达输出区，没有被 DOM 遮罩阻止；终端鼠标模式为 `none`。代码中为本地选区复制注册的 CSI 处理器拦截纯鼠标上报模式，原生/底部模式都使用同一处理器。用户确认原生 PageUp 能浏览旧记录，说明历史仍在 Claude 内部。
- 使用安装的 Claude 2.1.296，隔离配置、合成 20 轮/400 行已结束会话，通过 ConPTY 和真实 Electron/xterm 恢复；模型端点指向本机不可用端口，未发送任务。沿用项目鼠标拦截逻辑时，CLI 请求 `1000/1002/1003/1006` 鼠标模式，只输出可见内容；终端历史为 0，滚轮不能改变显示，反馈命令失败。
- 同一探针仅对 Claude 进程增加 `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1` 后，恢复得到 438 行历史余量、7008px 滚动范围；滚轮使位置从 438 移到 427，显示的测试记录随之变化，反馈命令通过。探针按 `viewportY` 比较实际显示内容，避免把始终不变的最新页误认为滚动失败。

结论：Claude 管理的虚拟历史与 RingCode 的本地鼠标/复制策略不兼容。刷新终端滚动条无法凭空产生 CLI 尚未输出的历史，因此前一轮 viewport 修正无法解决这一模式下的滚轮问题。

建议方案：只对 RingCode 启动的 Claude 与 Claude 分身设置该进程级兼容变量，让完整历史进入终端缓冲区，继续使用现有底部输入、选区复制和滚动条；不改 Claude 全局设置。代价是这些进程使用传统渲染。保留虚拟渲染则需单独转发鼠标滚轮并处理底部输入过滤，终端本身仍没有完整历史滚动条，改动与兼容范围更大。

依据：[Claude 官方 fullscreen 文档](https://code.claude.com/docs/en/fullscreen)，以及安装版本的实际恢复/滚轮对照。临时元数据日志位于系统临时目录 `ringcode-scroll-diagnostics.jsonl`，不含聊天正文、文件路径、密钥或键盘内容；修复验证阶段结束后移除诊断代码。
